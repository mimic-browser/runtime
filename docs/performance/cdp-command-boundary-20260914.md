# CDP geometry fixture command boundary correction

Final Linux race validation found a race between `Page.evaluateRealm` changing `realmEvaluationDepth` and the CDP pump reading it in `collectRealmOwners`. The affected geometry fixture called the embedding `Page.Evaluate` API directly after connecting a debugger session, which had started the independent Page pump.

This is an existing fixture ownership violation, not a new production synchronization contract. Source comparison against `f07bd2d643eebbadc28d582ef93f01c832a50106` found the complete DOM query test file, complete realm-owner collector file, evaluation depth guard, documented `LockCommands` contract and CDP pump command boundary unchanged. The [baseline proof](data/optimization-20260914/cdp-command-boundary/baseline-proof.json) records normalized source hashes. The [original integration log](data/optimization-20260914/cdp-command-boundary/integration-first-race.txt) preserves both race stacks, along with the other initial validation failures; those other failures are not attributed to this patch.

The minimal correction takes the existing `Page.LockCommands`/`UnlockCommands` boundary around each of this fixture's two direct evaluations. It preserves the embedding API's behavior and every geometry assertion, including resolved fallback font width and the error for unsupported `2ex` geometry. Unlock occurs before inspecting an evaluation error. No Page synchronization fields or runtime behavior change. Replacing only the depth counters with atomics would leave the rest of Page-owned task state unprotected and would not satisfy the existing command ownership contract.

Validation used a Go test source overlay against the integrated source, with no edit to production or the main checkout. A freshly built Linux race test executable ran `TestDOMContentQuadsUseResolvedControlFontGeometry` **20 times: 20/20 PASS**, with `MIMIC_FONT_DIR=/mnt/c/Windows/Fonts` supplying the same reference font family used by the Windows environment. This is a correctness run, not a performance measurement. The [raw run](data/optimization-20260914/cdp-command-boundary/linux-race.txt), [source receipt](data/optimization-20260914/cdp-command-boundary/source-receipt.json) and [binary hash](data/optimization-20260914/cdp-command-boundary/binary.sha256) are retained.

Patch SHA256: `56d6262b00b6ed3ad9363de5bfc507f39280d2df017e7dd37aa5bcabb65b6629`. This patch only corrects the identified test's fixture ownership. Other callers sharing a Page concurrently must continue to follow the same documented command boundary; no claim of an audit of all embedding callsites is made.

## Residual CDP fixture audit and complete race validation

The next full CDP race run found the same preexisting mistake in `TestContentQuadQueryDoesNotOverrideMouseHitTarget`, which performed additional direct evaluations after attaching CDP. The [second initial failure log](data/optimization-20260914/cdp-command-boundary/residual/full-race-before.jsonl) is preserved. A complete search of CDP test calls to `Evaluate`, `EvaluateFrame` and `EvaluateCommand` then checked their surrounding command boundaries.

All twelve direct `Page.Evaluate` fixture calls in `dom_query_test.go`, `dom_serialization_test.go`, `input_hit_target_test.go` and `input_order_test.go` now use the shared `evaluatePageFixture` test helper. It locks the Page, defers unlock, and calls the same embedding evaluation with `context.Background()`. This removes duplicated boundaries, including the first geometry correction, without nested locking. It changes no expression, assertion, geometry expectation or production code. The snapshot fixture's direct `Realm.Evaluate` and the wake fixture's `EvaluateCommand` already hold an explicit command boundary and remain unchanged.

A fresh test executable built with all five test files overlaid on the integrated root passed the **entire Linux CDP race suite in 41.477 s**, with `MIMIC_FONT_DIR=/tmp/mimic-reference-fonts`. The process exited 0 and no test failed or emitted a race warning. No additional competing jobs were started after this PASS. The [complete successful log](data/optimization-20260914/cdp-command-boundary/residual/full-race-after.jsonl), [audit and hashes](data/optimization-20260914/cdp-command-boundary/residual/audit.json), [source receipt](data/optimization-20260914/cdp-command-boundary/residual/source-receipt.json) and [binary hash](data/optimization-20260914/cdp-command-boundary/residual/binary.sha256) are retained. This suite duration is a validation record, not a benchmark claim.

Residual patch SHA256: `fea6b7a7ef3cf002f9b34c225f224555b62568d6ae768567831109a4c1dbb32a`. The earlier patch hash identifies the first restricted correction; this residual patch applies on top of it and consolidates its two calls into the common helper.
